# Rail Ninja Automated Tests

## Описание проекта

Проект предназначен для автоматизации тестирования веб-приложения Rail Ninja с использованием Java 17, Selenium WebDriver, Cucumber (Gherkin) и JUnit 5 для UI, а для API использовались Rest Assured и Jackson.

## Реализация тестов

### UI тесты

* **Структура:** Тесты построены с использованием паттерна Page Object Model (PO), что позволило создать отдельные классы страниц (`LandingPO`, `TimetablePO`, `PassengerPO`) с методами для взаимодействия с элементами страницы.
* **Cucumber:** Тесты реализованы через Cucumber и описаны в Gherkin формате, что обеспечивает удобочитаемое описание сценариев.
* **Выбор маршрута и станции:** Используются автодополнения с ожиданием видимости элементов и кликом по первой подсказке.
* **Дата рождения:** Работа с компонентами Ant Design (день, месяц, год) осуществляется отдельно с ожиданием видимости и кликабельности.
* **Пол и страна пассажира:** Выбираются через кликабельные элементы с использованием JavaScript для скроллинга и клика, чтобы обходить проблемы с невидимыми элементами.
* **Логирование и паузы:** Добавлено логирование и временные задержки для визуального контроля действий.


### API тесты

* Для тестирования REST API использовались **Rest Assured** и **Jackson**.
* Проверяются **статус-коды ответов**, структура JSON и корректность данных.
* Тестируются как **позитивные**, так и **негативные сценарии** (например, некорректные данные или пустые поля).

### Отчётность

* Для визуализации результатов используется **Allure**.

## Сложности реализации

* Динамические элементы и скрытые поля затрудняли выбор локаторов.
* Выпадающие списки Ant Design требовали ожидания и клика по видимому элементу.
* Иногда обычный `click()` не работал, использовался JavaScript click.
* Открытие новой вкладки потребовало пересоздания драйвера.
* Открытие разных версий (https://rail.ninja/trains/order/timetable) и https://rail.ninja/trains/order/v9/timetable) 
* Большой объем данных в JSON
